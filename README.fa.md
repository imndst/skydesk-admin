# اسکای‌دسک: پنل مدیریت فروش بلیت هواپیما و رزرو هتل

[English](README.md) | **فارسی**

Nuxt 3.17 (فرانت + بک Nitro، با ساختار پوشه‌ی Nuxt 4) · Nuxt UI 3 · SQLite · Zod · Vitest · Playwright · فارسی و راست‌به‌چپ · فونت وزیرمتن (محلی)

**ویژگی‌های اصلی:** تنظیمات سراسری قالب در پنل ادمین (توکن‌های طراحی + پیش‌فرض اجزای Nuxt UI)، رنگ‌بندی و چیدمان سبک سایت‌های رزرو سفر، رابط کاملاً فارسی، قیمت‌ها به تومان و تاریخ‌ها شمسی، نوار ناوبری پایین در موبایل.

---

## ۱. اجرا

پیش‌نیاز: **Node.js 20.18 یا بالاتر** (روی 20.18.2 تست شده؛ Node 22 و 24 هم کار می‌کنند).

> **چرا Nuxt 3.17 و Nuxt UI 3؟** Nuxt 4، Nuxt UI 4 و Vite 7/8 حداقل Node 20.19 می‌خواهند. برای اجرا روی Node 20.18 از آخرین نسخه‌های سازگار استفاده شده و چند وابستگی غیرمستقیم در بخش `overrides` فایل `package.json` روی نسخه‌ی سازگار قفل شده‌اند (`npm install` بدون هیچ هشدار EBADENGINE). کامپوننت‌های Dashboard در Nuxt UI 3 رایگان نیستند، بنابراین قالب صفحه (سایدبار، سربرگ، نوار پایین) با flex ساده پیاده شده است. اگر بعداً Node را به 22.22 یا 24 ارتقا دادید، می‌توانید به Nuxt 4 و Nuxt UI 4 مهاجرت کنید.

```bash
git clone https://github.com/imndst/skydesk-admin.git
cd skydesk-admin
npm ci                      # نصب دقیق همان نسخه‌های تست‌شده از package-lock.json
npm run dev                 # → http://localhost:3000
```

دیتابیس SQLite در اولین اجرا خودکار ساخته و با داده‌ی نمونه پر می‌شود (`data/skydesk.db`؛ برای ریست پاکش کنید).

ورود: **admin@skydesk.demo** / **Admin#2026demo**

نسخه‌ی production روی http محلی:

```bash
npm run build
npm run start:demo          # → http://localhost:3000 (در ویندوز هم کار می‌کند)
```

پشت HTTPS واقعی `npm start` (کوکی `Secure`). تنظیمات اختیاری در `.env.example` است.

## ۲. تنظیمات سراسری قالب (منوی «تنظیمات»)

### چه چیزی را مدیر می‌تواند تغییر دهد

| بخش | تنظیمات | روی چه چیزی اعمال می‌شود |
|---|---|---|
| رنگ‌ها | اصلی، تأکیدی، اطلاعات، موفقیت، هشدار، خطا، پس‌زمینه‌ی صفحه، سطح، حاشیه، متن، متن کم‌رنگ، سربرگ، طیف خاکستری | تمام اجزا (هر shade از ۵۰ تا ۹۵۰ خودکار ساخته می‌شود) |
| چیدمان | فونت، اندازه‌ی کلی رابط، گردی سراسری، حالت روشن/تیره، سبک سربرگ | کل پنل |
| دکمه | رنگ، سبک، اندازه، گردی، ضخامت متن، سایه | همه‌ی `UButton` ها |
| فیلدها | رنگ فوکوس، سبک، اندازه، گردی، ضخامت برچسب | `UInput`، `UInputNumber`، `USelect`، `USelectMenu`، `UTextarea`، `UFormField` |
| کارت‌ها | کارت (سبک، گردی، سایه)، نشان (سبک، اندازه، کپسولی)، تب (اندازه، گردی)، پنجره (گردی، محوشدن پس‌زمینه) | `UCard`، `UBadge`، `UTabs`، `UModal` |
| قالب‌ها | ۵ قالب آماده، خروجی توکن‌ها (W3C/Figma)، پشتیبان و بازیابی، بازنشانی | — |

### تجربه‌ی مدیر

- **پیش‌نمایش زنده:** هر تغییر بلافاصله روی کل پنل دیده می‌شود (فقط برای همان مدیر) تا «ذخیره» زده شود. پنل پیش‌نمایش، یک فرم جستجو و کارت هتل نمونه را نشان می‌دهد.
- **ایمنی تغییرات:** دکمه‌ی «بازگردانی»، هشدار هنگام خروج بدون ذخیره، و برگشت خودکار پیش‌نمایش اگر بدون ذخیره خارج شود.
- **دو مدیر هم‌زمان:** هر ذخیره نسخه دارد؛ اگر دیگری زودتر ذخیره کرده باشد خطای ۴۰۹ و پیشنهاد بارگذاری نسخه‌ی جدید.
- **بررسی خوانایی:** کنتراست WCAG هر ترکیب رنگ همان لحظه محاسبه و رنگ‌های ضعیف علامت زده می‌شوند.
- رنگ نیمه‌تایپ‌شده (مثل `#7c3`) قالب را خراب نمی‌کند؛ فقط مقدار معتبر اعمال می‌شود.

### معماری

```
تنظیمات ادمین (جدول settings، اعتبارسنجی با themeSchema)
   │
   ├─ buildThemeCss()     →  متغیرهای CSS: --color-sdprimary-50..950، --ui-radius، --font-sans، --sd-page …
   └─ buildUiAppConfig()  →  app.config.ui در Nuxt UI: defaultVariants (رنگ/سبک/اندازه) + کلاس‌های slot
```

همه در `shared/theme.ts`. افزونه‌ی `app/plugins/theme.ts` تنظیمات را هنگام رندر سمت سرور می‌خواند (بدون پرش ظاهر) و در مرورگر واکنش‌گرا به‌روز می‌کند.

**قانون صفحات:** در کد صفحات هیچ prop ظاهری داده نمی‌شود:

```vue
<UButton label="ذخیره" />                                       <!-- رنگ، اندازه، گردی… از تنظیمات -->
<UButton color="error" label="حذف" />                           <!-- فقط معنا: عمل مخرب -->
<UButton color="neutral" variant="outline" label="انصراف" />    <!-- فقط معنا: عمل فرعی -->
<UButton color="secondary" label="جستجو" />                     <!-- فقط معنا: فراخوان اصلی (CTA) -->
```

**افزودن تنظیم جدید:** یک فیلد به `themeSchema` و `DEFAULT_THEME` اضافه کنید، در `buildUiAppConfig` یا `buildThemeCss` به کلاس یا متغیر نگاشت کنید، و یک کنترل در `app/pages/settings.vue` بگذارید. تنظیمات قدیمیِ ذخیره‌شده خودکار با مقدار پیش‌فرض تکمیل می‌شوند.

### امنیت تنظیمات

- خواندن (`GET /api/theme`) عمومی است چون صفحه‌ی ورود هم قالب دارد (اطلاعات محرمانه ندارد، ETag دارد). نوشتن فقط با ورود و هدر CSRF ممکن است.
- هر مقداری که به CSS می‌رسد یا کد هگز معتبر `#rrggbb` است یا از یک جدول ثابت انتخاب می‌شود؛ متن آزاد کاربر هرگز به CSS یا کلاس نمی‌رسد. کلیدهای ناشناخته حذف می‌شوند.
- تست‌ها تزریق CSS، `url()`، تزریق کلاس، HTML در نام برند و نسخه‌ی قدیمی را بررسی می‌کنند.

### درباره‌ی رنگ‌ها

رنگ‌های پیش‌فرض آبی و نارنجی هستند، با نارنجی و آبی کمی تیره‌تر تا متن سفید روی دکمه‌ها استاندارد WCAG AA (کنتراست ۴٫۵) را پاس کند. نارنجی روشن مرجع (`#e67e00`) با متن سفید فقط ۲٫۹ کنتراست دارد. رنگ‌های روشن‌تر در قالب آماده‌ی **«کلاسیک روشن»** با یک کلیک قابل انتخاب‌اند و گزارش کنتراست، ضعف آن‌ها را نشان می‌دهد.

## ۳. تست

```bash
npm test              # build + ۸۰ تست (API، امنیت، قالب، performance) روی سرور ساخته‌شده
npm run test:only     # بدون build
```

تست مرورگری (۵ اندازه‌ی صفحه: 1440، 1024، 768، 390، 360):

```bash
npx playwright install chromium
npm run test:e2e
```

اگر کروم/کرومیوم روی سیستم نصب است: `CHROMIUM_PATH=/path/to/chromium npm run test:e2e`.

آنچه e2e بررسی می‌کند: نبود هم‌پوشانی عناصر و اسکرول افقی، دسترس‌پذیری WCAG 2 A/AA با axe، فرم‌ها و پیام‌های خطا، XSS در فرم، SQL در جستجو، و کل جریان تنظیمات قالب (پیش‌نمایش، ذخیره، اعمال روی صفحات دیگر، برگشت تغییرات ذخیره‌نشده).

## ۴. امنیت (کل پروژه)

| تهدید | راهکار |
|---|---|
| SQL Injection | فقط prepared statement با پارامتر؛ `sort` از لیست مجاز؛ escape برای `LIKE`؛ شناسه فقط عدد صحیح |
| XSS | Zod ورودی `< >` و کاراکتر کنترلی را رد می‌کند + `xssValidator` + escape خروجی Vue (بدون `v-html`) + CSP با nonce |
| Injection دیگر | حذف فیلدهای اضافی بدنه، محاسبه‌ی مبلغ فقط در سرور، سقف ۲۰KB برای بدنه، بی‌اثر بودن prototype pollution |
| CSRF | کوکی `HttpOnly` + `SameSite=Strict` + هدر اجباری + بررسی `Origin` |
| احراز هویت | scrypt، نشست امضاشده HMAC، پیام یکسان برای کاربر ناموجود/رمز غلط |
| Brute force / DoS | قفل بعد از ۵ ورود ناموفق، ۶۰۰ درخواست در دقیقه برای هر IP |
| هدرها | CSP، X-Frame-Options، nosniff، HSTS، Referrer-Policy، بدون CORS |

## ۵. Performance (هدف کمتر از ۱۰ میلی‌ثانیه)

`tests/perf.test.ts` برای هر endpoint سیصد درخواست می‌فرستد و p95 سمت سرور و رفت‌وبرگشت را با سقف ۱۰ms چک می‌کند (جدول نتایج در خروجی `npm test` چاپ می‌شود). روی ماشین تست، p95 سمت سرور زیر ۱ms و رفت‌وبرگشت زیر ۷ms بود. تنظیمات قالب در حافظه کش می‌شود و هر رندر به دیتابیس نمی‌رود.

استثناها: ورود عمداً کند است (scrypt). رندر HTML سمت سرور صفحات در آخرین اجرا p95 حدود ۱۲ms بود (بسته به ماشین تا ۵۰ms) و تضمینی برای زیر ۱۰ms ندارد.

## ۶. ساختار

```
shared/theme.ts         توکن‌ها، اسکیما، قالب‌های آماده، نگاشت به CSS و Nuxt UI
shared/schemas.ts       اعتبارسنجی مشترک فرانت و بک (پیام‌های فارسی)
app/plugins/theme.ts    اعمال قالب در SSR و مرورگر
app/pages/settings.vue  صفحه‌ی تنظیمات قالب
app/components/         AppPage، BottomNav، ThemePreview، ColorField، ContrastReport، …
server/api/theme.*.ts   خواندن و ذخیره‌ی قالب
server/utils/theme.ts   کش و کنترل نسخه
tests/  e2e/            تست‌ها
```

## ۷. محدودیت‌ها

- ورودی‌های تاریخ مرورگر میلادی هستند؛ نمایش تاریخ‌ها شمسی است. برای ورود شمسی باید یک date picker شمسی اضافه شود.
- رنگ‌های سطح و متن فقط در حالت روشن قابل تنظیم‌اند؛ حالت تیره از طیف خاکستری انتخابی ساخته می‌شود.
- پیش‌نمایش زنده فقط در همان تب مدیر است؛ کاربران دیگر تغییر را بعد از بارگذاری بعدی صفحه می‌بینند.
- اگر حالت رنگ «همیشه روشن/تیره» باشد و سیستم کاربر برعکس، اولین بارگذاری ممکن است یک لحظه با حالت سیستم نمایش داده شود.
- پرداخت، صدور بلیت و اتصال به تأمین‌کننده ندارد؛ موجودی هتل وابسته به تاریخ نیست؛ یک کاربر ادمین بدون نقش‌بندی.
- SQLite و محدودکننده‌ی نرخ در حافظه برای یک سرور مناسب‌اند.
